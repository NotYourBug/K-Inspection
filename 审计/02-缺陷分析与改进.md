## 发现的具体缺陷（按严重程度排序）

### 🔴 缺陷 1：缺少 etcd 健康检查

**位置**：`k8s_inspector/checks.py`

**现状**：`check_control_plane()` 只检查：
- apiserver `/healthz` 端点的健康状态和延迟
- kube-apiserver / kube-controller-manager / kube-scheduler Pod 是否为 Running

**缺失**：README 巡检维度表中明确列出了 etcd 巡检要求（成员健康、磁盘使用率 < 80%、leader 切换 < 1次/天），但代码中完全没有对应检查。

**影响**：自建 etcd 的集群将缺乏 etcd 层面的故障检测，这是控制面最关键的组件之一。

**建议实现**：
```python
def check_etcd(core: client.CoreV1Api, cfg: InspectorConfig) -> CheckResult:
    """检查 etcd 集群健康状态"""
    # 1. 找到 etcd Pod（标签 component=etcd 或 app=etcd）
    # 2. 通过 exec 或 metrics 检查 etcd 成员健康
    # 3. 检查 etcd 磁盘使用率（通过 Prometheus 指标或直接 df）
    # 4. 检查 leader 切换频率
    ...
```

### 🟡 缺陷 2：Pod 检查重复调用 `_pod_issue_from_obj`

**位置**：`k8s_inspector/checks.py:226-231`

**现状**：
```python
issue = _pod_issue_from_obj(p, restart_threshold=0)   # 第一次调用
if issue:
    bad.append(...)
    continue
issue2 = _pod_issue_from_obj(p, restart_threshold=cfg.thresholds.pod_restart_count)  # 第二次调用
```

**问题**：`_pod_issue_from_obj()` 在第一次调用时已经遍历了所有ContainerStatuses，而第二次调用对同一个 Pod 又遍历一遍，产生了冗余的 API 数据遍历。

**建议**：改为一次性同时返回 bad issue 和 restart 信息：
```python
def _pod_issue_from_obj_v2(pod, restart_threshold):
    """返回 (issue_or_none, restart_issue_or_none)"""
    ...
```

### 🟡 缺陷 3：检查串行执行导致耗时较长

**位置**：`k8s_inspector/checks.py:485-540`

**现状**：`run_all()` 中 6 个检查函数是严格串行调用的。

**问题**：各检查函数之间无数据依赖（都只读 K8s API），分别查询不同的 API 资源。在 full profile 下，全部串行执行可能耗时 10-20 秒。

**建议**：使用线程池并发执行：
```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=4) as executor:
    futures = {
        executor.submit(check_control_plane, core, api_client, cfg): "control-plane",
        executor.submit(check_nodes, core, custom, cfg, True): "nodes",
        # ...
    }
    for future in as_completed(futures):
        results.append(future.result())
```

**注意**：需要维持结果的原始顺序，或者给结果加序号后再排序。

### 🟡 缺陷 4：HTML 报告缺少详细数据展示

**位置**：`k8s_inspector/report.py:44-104`

**现状**：HTML 报告只渲染了 name/status/summary/duration_ms 四个字段，`data` 字典中的关键信息（NotReady 节点列表、异常 Pod 列表、pending PVC 列表）完全不展示。

**建议**：在每行后增加可折叠的 `<details>` 区域，渲染 data 中的列表数据。

---

### 🟢 缺陷 5：错误信息吞没部分有用上下文

**位置**：`k8s_inspector/checks.py:152-159`（及其他 catch 块）

**现状**：`data={"error": str(e)}` 只保留了 `str(e)`，对于 K8s ApiException 来说，丢失了 HTTP status code、reason 等结构化信息。

**建议**：对 `ApiException` 做特殊处理，保留 `status` 和 `reason`：
```python
except ApiException as e:
    data = {"error": str(e), "api_status": e.status, "api_reason": e.reason}
```
